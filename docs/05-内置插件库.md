# 随手 · 内置插件库

插件为声明式包(manifest.json + 数据文件,不执行用户代码),在插件市场启用/禁用。仓库 `plugins-market/`;全局安装目录 `~/Library/Application Support/MarkNote/plugins/`。

> **现在的插件市场只有主题包。** 原先以插件分发的渲染增强已**全部内置**（资源目录
> `Sources/MarkNote/Resources/renders/`，随预览页直接加载，无需安装、无需启用）：
> `alert`(告警横幅) · `badge`(状态徽章) · `tabs`(标签页) · `timeline`(时间线) ·
> `term`(终端块) · `kbd`(键帽) · `mention`(提及) · `quote`(引用卡片) ·
> `imagefig`(图片图注) · `copy`(代码块复制按钮)。
> 模板 / AI 专家 / 文件类型 / 命令四类插件包已下线，包体移到
> `~/Library/Application Support/MarkNote/_removed-plugins-<日期>/` 备份，需要可恢复。

> 三套主题目前都是**亮色单主题**：暗色版本已撤下（`Bubble Pop · 夜` / `墨纸 · 夜`），
> 之后会按 v4 规则重做再上；`dawn` / `night` 两侧都指向同一套亮色纸色。

> 主题字体桥：主题声明 `uiFont` / `displayFont` / `codeFont` 后，预览的正文、标题、代码
> 会自动套用对应字体（宿主写入 `--theme-ui-font` / `--theme-display-font` /
> `--theme-code-font`），主题 CSS 只需要负责颜色与细节。

> 晨曦 / 夜航者仅作为“未安装任何主题插件”时的内部兜底，不出现在视图菜单或主题选择器中。

> **主题硬门槛（扫描阶段执行，不达标直接不进主题列表）**
>
> 0. 人工审核：必须有用户看过设计稿并批准，`reviewed: true` 且 `reviewedHash` 与当前内容哈希一致；
>    主题内容任何变化（CSS / 字体 / 任意图标）都会自动失效，退回待审核
> 0.1 主题兜底：必须至少启用一个主题包；关闭最后一个会被阻止。若启动时发现全部关闭，
>     自动启用兜底包（墨纸优先），绝不回退到内置晨曦 / 夜航者。
> 1. 专属字体：至少 `uiFont` 或 `displayFont`，且必须有 `codeFont`
> 2. 专属图标：必须覆盖随手全部语义槽位，未知键（如 Codex 的 terminal/code/play/check）直接判不合格
> 3. 专属彩蛋：必须声明 `easterEgg`
> 4. 专属特效/动画：必须声明 `motion`，且尊重系统“减少动态效果”
> 5. 可读性：正文对比度 ≥4.5:1，次级文字 ≥3.5:1，强调文字 ≥4.0:1
> 6. 资源体积：单字体 ≤12MB、单图标 ≤256KB、CSS ≤256KB

> **`auditVersion: 4` 追加的门槛**（更严格，新主题必须满足；v3 主题保持原状不追溯）
>
> 7. 预览变量齐备：`--surface` `--text-secondary` `--border` `--border-strong` `--accent-soft`
>    `--code-bg` `--code-text` `--hl-kw/str/num/comment` `--note/tip/warn/danger/info` 及各自 `-bg`
>    缺任意一个都判不合格（预览会出现与主题无关的默认色）
> 8. 代码高亮可读：`--hl-*` 在 `--code-bg` 上对比度 ≥3.0:1
> 9. 提示块可读：`--note/tip/warn/danger/info` 按「自身 `-bg` 叠在 `--bg` 上」的真实观感 ≥4.0:1
> 10. 禁止渐变：CSS 中出现 `gradient(` 直接拦截（纯色才耐看、也不会拖性能）
> 11. 标题专属字体：必须给 `.markdown-body h1…h4` 声明 `font-family`
> 12. 动效至少 2 项（氛围 / 图标签 / 页签弹簧任选），时长仍在 120–600ms
> 13. 图标必须 ≥64×64 且为正方形（含非文件类图标）

> **多彩（v4 起对亮色主题的审美要求）**

> **`auditVersion: 5` 追加：编辑器语法配色（必填 + 可量化区分度）**
>
> 编辑器不再使用写死的系统色，而是读当前主题声明的 `--md-*`；没有主题（内部兜底）时才回落到内置配色。
> **预览与编辑器共用同一套 `--md-*`**：有序 / 无序 / 任务列表标记、表格边框与表头、粗体 / 斜体 /
> 删除线 / 高亮 / 插入 / 行内代码 / 链接 / 引用 / 分隔线在预览里同样按主题声明上色 ——
> 左右并排时同一种语法同一种颜色，一眼能对上「哪些语法生效了」。
> 主题必须声明 **33 个** 语法色，覆盖渲染器支持的全部语法（这样在编辑器里一眼就能看出哪些语法生效了）：
>
> | 分组 | 变量 | 要求 |
> | --- | --- | --- |
> | 内容（12） | `--md-h1/h2/h3` `--md-bold` `--md-italic` `--md-code` `--md-link` `--md-quote` `--md-math` `--md-highlight` `--md-strike` `--md-insert` | 纸底对比 ≥4.5:1；两两 ΔE ≥12 |
> | 主色（6） | `--md-h1/h2/h3` `--md-bold` `--md-italic` `--md-code` | 两两 ΔE ≥22（标题三级、粗体、斜体、代码必须一眼分得开） |
> | 语义（10） | `--md-callout` `--md-table-head` `--md-embed` `--md-kbd` `--md-mention` `--md-emoji` `--md-badge` `--md-timeline` `--md-term` `--md-mermaid` | 纸底对比 ≥4.5:1 |
> | 结构 / 标记（9） | `--md-marker` `--md-url` `--md-list` `--md-number` `--md-task` `--md-hr` `--md-table` `--md-fence` `--md-html` | 纸底对比 ≥3.0:1，且 Lab 彩度 ≤30（结构可见但不跟内容抢色） |
> | 底纹（2） | `--md-code-bg` `--md-highlight-bg` | 与正文对比 ≥4.5:1（通过内容色保证） |
>
> 覆盖的语法：标题 1–6、粗体、斜体、行内代码、代码围栏（含 mermaid）、链接、链接地址、图片 / 视频 / 音频 / 附件、
> 引用、无序 / 有序 / 任务列表、时间线、终端命令、分隔线、表格（表头 / 分隔行 / 竖线）、公式（行内 + `$$` 块）、
> 高亮、删除线、插入、脚注、TOC、锚点、上下标、Emoji、键帽、提及、徽章、Callout / 告警、HTML 标签。
> **标记与内容分开上色**：`#`、`**`、`~~`、`==`、`++`、`|` 等标记走标记色（中性），内容走内容色。
>
> 亮色主题不要「一个主色 + 大片白纸」，要做到**色彩丰富但和谐**：
>
> - 文件类型图标各占一个色相（文件夹 / Markdown / 代码 / 数据 / 图片 / 视频 / 音频…），
>   色相之间保持同一明度带，避免某一类跳出来；
> - 预览层级各自有色：主题可在 CSS 里声明 `--h1 / --h2 / --h3 / --strong / --em / --hr`，
>   预览页会自动套用（不声明则回落正文色，老主题不受影响）；
> - 提示块五色（note / tip / warn / danger / info）与代码高亮四色都要真用上，不要一片同色；
> - 所有彩色文字仍要过对比度门槛（正文 ≥4.5、次级 ≥3.5、主色文字 ≥4.0、高亮 ≥3.0、提示 ≥4.0）。

- 亮 / 暗：主题可以只做亮色，也可以只做暗色。只做一侧时，CSS 里把 `dawn` / `night` 两个变体
  都指向同一套纸色（参考 `theme-sumi-paper/sumi-day.css` 的写法），菜单里选哪一侧都保持同一外观，
  避免出现「亮色纸 + 暗色控件」的半成品混搭。

### 主题包扩展字段

`theme.json` 条目除 `id/name/desc/cssFile/swatchHex` 外，质量合格主题示例：

```json
{
  "reviewed": true,
  "uiFont":     { "file": "fonts/ui.ttf", "family": "字体家族名", "size": 12 },
  "codeFont":   { "file": "fonts/code.ttf", "family": "等宽字体家族名", "size": 12 },
  "displayFont":{ "file": "fonts/title.ttf", "family": "标题字体家族名", "size": 12 },
  "icons": {
    "folder": "icons/folder-64.png",
    "puzzlepiece.extension": "icons/plugin-64.png",
    "shippingbox": "icons/plugin-64.png",
    "gearshape": "icons/settings-64.png",
    "sidebar.left": "icons/sidebar-64.png",
    "magnifyingglass": "icons/search-64.png",
    "sparkles": "icons/sparkle-64.png",
    "clock.arrow.circlepath": "icons/branch-64.png",
    "paw": "icons/paw-64.png"
  },
  "easterEgg": {
    "trigger": "icon-click",
    "clicks": 5,
    "symbols": ["🫧", "🍬", "✨"],
    "message": "Bubble Pop!"
  },
  "motion": {
    "ambientBubbles": true,
    "iconBounce": true,
    "tabSpring": true,
    "durationMs": 280,
    "respectReduceMotion": true
  },
  "glass": 0.16
}
```

- 字体随包加载，选中主题后注册到编辑器并注入预览 `@font-face`
- 字体与窗口透明度完全由主题控制；用户侧不再提供自定义字体导入与透明度滑杆
- `icons` 必须覆盖全部语义槽位；未覆盖或出现未知键都会在扫描阶段被拦截
- `easterEgg.trigger` 目前支持 `icon-click`：侧栏主题图标连续点击 `clicks` 次触发
- `motion` 只使用轻量 SwiftUI 动画；开启系统“减少动态效果”时自动降级为静态
- 未审核主题只放在 `plugins-market/_review/<id>/` 生成评审图，不安装、不启用、不进主题列表

## 说明

## 插件隔离规则（所有非主题插件必须遵守）

> 结论先行：**插件默认隔离**。不做「跟随工作台自动切换」，也不做「全局共享数据」；
> 唯一的跨工作台数据流动是**用户显式勾选的一次性导入**。

1. **作用域 = 当前工作台**
   每个工作台是独立环境（VSCode 工作区语义）。素材、卡片墙、索引类插件只读当前工作台，
   面板不提供「全部工作台」这类聚合视图。切换工作台在 **设置 → 工作台** 里完成。

2. **跨工作台只允许「显式勾选导入」**
   - 入口只有一个：面板上的「从其他工作台导入…」，弹出按工作台分组的**可勾选列表**；
   - 导入 = **复制**到当前工作台，原工作台**只读**、绝不被修改；
   - **禁止跨工作台引用**（否则搬走/备份其中一个库就会断图）；
   - **禁止自动同步、自动合并**素材或笔记；
   - 同名冲突：**自动加序号**，不覆盖任何已有文件。

3. **不搞批量改名**
   不提供「一键整理历史图片」这类批量重命名/移动功能（风险高、收益低）；
   素材入库时就按「日期-描述」命名，历史文件保持原样。

4. **读写边界**
   - 只读：复用现有目录索引与正文缓存，不新建数据库、不扫无关目录；
   - 只写：当前工作台自己的目录（如 `source/`），且每一步可撤销；
   - 不碰：编辑器内核、渲染管线、别的工作台的文件、别人的笔记内容。

5. **只有「本机 UI 偏好」可以跨工作台**
   主题、排版偏好、快捷键、阅读位置这类**不进入笔记文件**的本机偏好，切换工作台时保持不变；
   除此之外的一切数据都不共享。

6. **卸载即干净**
   卸载后剩下的只能是标准 Markdown 与本机偏好；不留自定义格式、不留垃圾文件。

### 阅读专注态（内置功能，随预览提供）

- **进入**：`⌘⇧R`（视图 → 阅读模式）；预览里**双击正文空白**也可进入
  （双击链接 / 图片 / 代码 / 表格 / 已选中文本时不触发）。
- **界面**：隐藏侧栏、AI 面板、标签栏与状态栏，只留预览正文全宽阅读；退出即完全还原。
- **退出**：`Esc`、开始打字（回到编辑），或把鼠标移到窗口顶部 8pt —— 滑出退出条后点 ✕。
- **零持久化**：专注态是临时 UI 状态，不写任何偏好、不碰笔记文件；预览滚动位置保持不变。

### 卡片墙交互约定（view-note-cards）

- **只读**：只读当前工作台的笔记（标题 + 正文前几行），不移动、不改名、不改内容；素材文件不进卡片墙。
- **筛选**：全部 / 加星 / 待办（含未勾选 `- [ ]` 的笔记）；卡片信息行带**待办进度徽章**（未完成 / 总数）。
- **分组**：今天 / 昨天 / 具体日期，组内按修改时间倒序。
- **星标与筛选状态 = 本机 UI 偏好**（UserDefaults）：切换工作台保持不变，不写入笔记文件。

### 素材网格交互约定（view-asset-grid）

- **一套写法，按类型分派**：面板的「插入 / 复制引用 / 拖拽」三处共用同一套生成逻辑，产物完全一致：

  | 素材类型 | 写入编辑器的语法 | 预览表现 |
  |---|---|---|
  | 图片（png/jpg/gif/webp/heic…） | `![名称](img/x.png)` | 行内图片 |
  | 视频（mp4/mov/m4v/webm/mkv/avi） | `<video src="source/mp4/x.mov" controls></video>` | 内嵌播放器（主题圆角/边框/悬浮动效） |
  | 音频（mp3/m4a/wav/flac/aac/ogg…） | `<audio src="source/audio/x.mp3" controls></audio>` | 内嵌播放器 |
  | 其他文件（pdf/zip/docx/xlsx…） | `@[名称](source/pdf/x.pdf)` | 附件卡（点击打开） |

- **视频 / 音频不当图片处理**：不再用 `![]()` 伪装（旧写法在预览里仅作兼容识别）。
  素材网格内视频显示**首帧缩略图 + 时长角标**（首帧后台生成、按路径内存缓存，不卡网格滚动）。
- **块级独占整行**：`<video>` / `<audio>` / 附件卡插入时自动补齐首尾换行（拖到哪插到哪，不与相邻内容挤一行）；
  行内图片保持原样。
- **路径编码**：含空格 / 括号 / `#` 的路径做百分号编码（保留中文），避免破坏 Markdown 与附件卡解析。
- **拖进编辑器 = 落点插入**：拖到哪儿插到哪儿（不是插到光标处）；只插入引用文本，
  **不复制文件、不产生新素材**，拖拽与手动插入等价。
- **只拖当前工作台**：拖拽来源只能是当前工作台的素材网格（隔离规则第 1 条）；
  跨工作台素材先经「从其他工作台导入…」复制进来，再拖。
- **外部拖入自动入库**：把图片 / 视频 / 音频 / 文档从 Finder 拖进窗口（编辑器、侧栏、预览区均可）
  或 ⌘V 粘贴文件 → **复制**进 `source/<type>/`，命名 **「日期-描述」**
  （日期取来源文件修改时间 `MM-dd`，描述取原文件名主体并剔除时间戳噪声）；
  编辑器打开时同时插入对应语法的引用，源文件保持不动。
  文本 / 笔记类（md / txt / 代码）不走素材入库，仍按「导入为笔记」处理。
- **删除 = 移到废纸篓**：选中素材点删除，先提示「被 N 篇笔记引用」（引用将失效），
  确认后移入系统废纸篓（可随时恢复）；不做不可逆删除、不静默清理。

### 流程图交互约定（view-flowchart）

画流程图的工具：图形、连线、文字、分组、样式，导出 PNG。**只在当前工作台读写**。

| 项 | 约定 |
| --- | --- |
| 存放 | `<工作台>/source/flowchart/<名字>.json`（纯 JSON，可读可进 git；同名自动加序号，绝不覆盖） |
| 产物 | PNG 导出到 `~/Downloads/随手导出/`（1x / 2x / 3x；背景可选主题纸色 / 白色 / 透明；不含网格与选中框） |
| 保存 | 编辑后 0.9 秒防抖自动保存；`⌘S` 立即保存 |
| 删除 | 图文件走系统废纸篓（可恢复），不静默删除 |

- **自环**：起点和终点是同一个框也能连（拖拽、点击-点击、端点改接都行）。线从一条边探出去、

### 素材采集交互约定（view-collector）

一句话需求 → AI 解析成需求卡片 → 缺字段追问 → 开工确认 → 搜索 → 候选勾选 → 入库。
结果不自动落地：**勾选哪些才下载哪些**。图片进 `source/image`（命名沿用工作台约定「日期-描述」），
视频保存为收藏条目（标题 / 时长 / 链接 / 本地封面）。

**AI 追问（2026-09）**：一句话解析完**先自审一遍**——「找什么类型 + 具体对象」不明确、
或关键项（图片用途与方向、视频时长与平台、文章体裁与范围、小说书名与章节数）无法安全推断时，
先进入**追问页**再开工：每轮最多 3 条问题，每条给 2-6 个**贴合上下文、可直接点**的选项（也可自己写），
底部可「不问了，直接看需求卡」跳过。
回答会拼成「追问补充」喂回解析器重填需求卡，然后**再审一轮**——问清（`ready=true`）或问满
**3 轮**才放行（`CollectorClarify.canAskMore`）；模型调用失败一律放行，绝不把用户锁在问答里。

**「选完选项也要接着问」（2026-09 修订）**：追问的开关不只是模型说了算，硬规则优先 ——

- **关键项体检**（`missingKeyFields`）：类型、主题，以及各类型最影响结果的那一项
  （图片的用途/方向、视频的时长/平台、文章的体裁或范围、小说的章节范围）没确认就**必须继续问**，
  即便模型已经返回 `ready=true`；能安全默认的（数量、语言、是否合并文件）不算缺口，不拿来烦人。
- **最少 2 轮**（`minRounds`）：答过一轮（哪怕是点了选项）之后，还会再确认一轮「还有没有硬要求」——
  避免「选了一个选项 = 已经理解」。
- 每轮只问「下一步最该确认的那一件」，硬规则的问题排在模型的问题前面，合并后仍**最多 3 条**、
  最多 3 轮；每轮都保留出口：底部「不问了，直接看需求卡」，以及选项里的「没有了，就这样」
  （`answerMeansStop` 命中即停，回答照常回填需求卡）。
追问页排版对照图：[collector-clarify.png](screenshots/collector-clarify.png)。
审校原则写在 prompt 里：只问**会影响采集结果**的问题，能安全默认的（数量、语言等）不问，
用户已经说过的重复问会被拒（`ready` 与 `questions` 矛盾时按「没问完」处理）。

### 站点账号（2026-09：登录后采集才拿得全）

### 贴链接导入与搜索过滤（2026-09-18）

**贴链接导入**：输入页多了「贴链接导入」入口 —— 把你自己在浏览器 / App 里看到的地址一行一条贴进来，
直接抓成候选（默认全选，点一次「采集选中」即可）。支持三类：

| 链接类型 | 处理方式 |
| --- | --- |
| 图片 / 视频直链 | 按扩展名识别，直接下载（视频走直链下载） |
| 社交平台帖子（X、微博…） | 读页面里的 `og:video` / `og:image` 取媒体；普通 HTTP 抓不到就用应用内浏览器渲染一遍 |
| 文章网页 | 走正文提取 → 转 Markdown 笔记（与文章采集同一条链路） |

边界（写进产品而非口号）：**只读你能看到的内容** —— 用你本机的登录会话（站点账号），
不绕过登录 / 年龄 / 付费门槛，不做平台批量爬取；失败逐条报原因。

**搜索过滤三档**：「严格 / 适中 / 关闭」，映射到搜索引擎参数（Bing `adlt=strict|moderate|off`）。
关闭前会做一次**成年确认**（本机记一次），并明确告知：只影响搜索参数，站点自身的门槛不会被绕过。
插件本身不审查、不修改你已有的本地内容。

**采集专用代理**（`CollectorNet`）：来源与筛选里可填 `host:port`（如 `127.0.0.1:7890`），
只作用于采集插件，不动系统设置。**实测**：当前网络下 `x.com` 与 `pbs.twimg.com` / `video.twimg.com`
全部不可达（HTTP 000），所以 X 相关内容**必须挂代理**才能采集；挂上后走的是同一套抓取链路。

**X（Twitter）实测记录（2026-09-18，系统代理 127.0.0.1:7890）**：

| 检查项 | 结果 |
| --- | --- |
| 代理连通性 | `x.com` / `pbs.twimg.com` / `video.twimg.com` / `api.x.com` 全部 200（直连均 000） |
| 普通 HTTP 抓取帖子页 | 能拿到 300KB 外壳，但**没有 og 标签**（X 是纯 JS 应用） |
| 应用内浏览器渲染 | 成功；从渲染结果解析出 `pbs.twimg.com` 媒体地址（主页头像/封面已验证） |
| 登录态 | 本机 App 里有 X 登录 cookie（1291 字符），渲染时带着它 |
| 时间线里的 `video.twimg.com` | 只出现在 CSP 白名单，不是媒体直链；X 用 blob/MSE 播放，媒体要打开**单条帖子页**才拿得到 |

结论：X 的链路是「**单条帖子页** → og 标签 / 页面数据里的 twimg 直链 → 下载」。
贴的是帖子链接就按这条走；贴主页链接只能拿到封面图。

#### 实测：登录到底让采集好多少？（2026-09-14 用本机登录态量的）

方法：同一批页面分别用「游客」和「本机登录 cookie」各抓一次（`CollectorLoginEffectLiveTests`，
`RUN_NET_TESTS=1 LIVE_APP_COOKIES=1` 才跑，只读 cookie 不打印内容）。

| 维度 | 实测结果 | 结论 |
| --- | --- | --- |
| 公开文章正文 | 掘金 7071→7071 字 · 少数派 2545→2545 字 · 豆瓣 11080→11080 字 | **登录没差别**：这些站本来就不拦 |
| 图片下载 | 少数派 6/6 → 6/6 · 豆瓣 5/6 → 5/6（失败的那张两边都失败） | **登录没差别**：图不是登录墙挡的 |
| B 站画质 | 未登录 360P，登录 1080P | 登录**确实**提升（这条是真的） |
| JS 渲染站 | 知乎专栏：普通 HTTP 74 字 → 应用内浏览器渲染 120 字，渲染出来是「打开知乎 App」 | 登录也救不了，**要专用接口** |

**所以别把「登录」当质变开关**。真正让采集质量变好的是这几件（都已在做）：
失败必须说清楚（不再静默少几个）、防盗链 Referer 三档回退 + 缩略图兜底、
站点表只留能用的一手来源、正文直接转 `.md`。

**应用内浏览器渲染兜底**（`CollectorWebRender`）：普通 HTTP 抓回来太薄（< 200 字）时，
用 WKWebView 跑一遍再取 DOM —— 它复用站点账号的 cookie store，所以登录过的站渲染出来就是登录态。
实测对静态站只有小幅提升（掘金 +79 字、少数派 +113 字），对知乎这类强反爬站仍然不够。
要真正拿下知乎 / 小红书，得按站点写专用接口（App API / 签名），那是下一步。

#### 强反爬站（小红书 / 知乎）：调研结论与「不内置」的决定（2026-09-14）

这类站早就有人做，路子也公开，主流是三条（都是「不逆向算法，让页面自己算」）：

| 项目 | 星数 | 手法 |
| --- | --- | --- |
| **MediaCrawler** | ★64.9k | Playwright 保登录态；**CDP 模式直接读页面发出的接口响应**；或页面里执行 JS 取签名参数（小红书 `window._webmsxyw` → `X-s`/`X-t`） |
| **Spider_XHS** | ★7.6k | 小红书专用：签名逆向 + 笔记接口 |
| **xhshow**（Cloxl） | — | 把小红书签名 JS（`xhs_webmsxyw.js` / `_common.js`）单独抽出来跑，产出 `X-s`/`X-t`/`X-s-common` |

**决定（2026-09-14）：不把站点专用逆向/签名代码内置进 App。**

理由：采集是**通用插件**。把「小红书的 x-s 签名实现」「知乎的 x-zse-96 签名 JS」这类
站点专用的逆向代码打进核心里，等于把插件变成"某几个站的爬虫合集"——
维护面（站点一改就得跟）、合规面（绕过站点保护措施）和插件定位（通用素材采集）全都被破坏。
所以这轮为签名做的实验代码（`XiaohongshuAPI`、接口截获 `captureAPI`、会话/弹窗拦截 `Session`）
**已全部删除**，只保留真正通用的能力：

- `CollectorWebRender.render`：正文太薄（< 200 字）时用应用内浏览器渲染一遍再提取
  —— 对**所有**站点一视同仁，不针对某个站做特殊处理；
- 站点账号（cookie 按域名注入）与「失败必须说清楚」照旧。

**现状（如实）**：小红书、知乎这类「必须带签名接口 / App 专属道具」的站，**当前不支持** ——
采集会如实报「打不开页面 / 正文只有 N 字」并提示登录，不会假装成功。

**如果以后真要做**，正路是把它们做成**独立插件包**（用户按需安装、自己承担站点条款与风险），
而不是进核心：可参考 MediaCrawler（★64.9k，CDP 读响应 / 页面内跑签名）、
Spider_XHS（★7.6k）、xhshow（MIT，纯算实现）——技术路线都是「不逆向算法，让页面自己算」。

需求卡片给**尽量详细的选项**（全部可选，默认「不限」；AI 解析能填的会替用户填好）：

| 分组 | 选项 |

**预览与格式**：预览里点击图片 = 看大图 —— 点击时回传的是**原始引用路径**（内联成 data URL 后
用 `data-img-path` 带着原路径，宿主再解析原图），不会把 `data:` 当文件去打开（那会弹「无法打开」）；
找不到原图时给一句轻提示，不弹系统错误。老笔记里「文件名带空格又没编码」的引用会在渲染前自动补编码，
不再整张不显示。图注只认**显式写的说明**（`![图](路径 "图注")` 或 `{caption=…}`），不再拿 alt（常是文件名）
当图注；设置 → 编辑 → 预览里可一键「图片下方显示图注」开关。

候选卡左下角有预览入口（图片=放大镜 → 大图可缩放 0.2~4 倍、适应窗口 / 100%；
视频=播放键 → 有直链就内嵌播放，没有直链则看封面 + 打开来源页；双击卡片也能打开预览）。
下载回来的字节会**按文件头识别真实格式**（PNG / JPEG / GIF / WebP / AVIF / HEIC / BMP / TIFF）——
图站常把 WebP 挂在 .jpg 名下，按名字存会变成「坏图/显示不全」；HTML 错误页一律丢弃不入库。
素材库的缩略图改为完整显示（不裁切），本地图片可预览、本地视频可直接播放。

**提示词历史**：每次点「开始采集」都会记一条 —— 既有**手动输入的提示词**，也有
**选项总结出来的提示词**（如「找 12 个图片：赛博朋克霓虹街道（横图 · ≥4K · 色调 冷色 ·
主色 蓝/粉 · 无水印）」），外加实际使用的搜索词与整张需求卡。历史在输入页列出，
可「再用一次」（整张卡恢复，直接改改就能用）、单条删除或清空；采集结束后回填「已入库 N」。
记录按**工作台**分开存在 `~/Library/Application Support/MarkNote/collector-history/`（不写进工作台目录）。

选项会真的落到搜索上：拼进中英搜索词（主题 + 风格 + 色调 + 主色 + 方向 + 尺寸 + 无水印…），
并转成站点筛选参数（尺寸 / 方向 / 类型 / 授权 / 时效 / 时长），站点限定与排除拼成
`site:xxx` / `-site:xxx`。关键词语言可选中文 / 英文 / 中英各一条。

**下载进度（2026-09）**：点「采集选中」后，底部出现主题化进度条 ——
「阶段 · 条目名」+「第几个/共几个 · 已下/总长」+ 百分比，正在下载的那张候选卡缩略图底部
也叠一条同款细进度条。视频下载改成**边下边写盘**（几百 MB 不再整份吃内存），
超过 300MB 立刻掐断（提示体积上限），临时的「.part」文件按字节嗅探真实格式（ftyp / EBML）
再定扩展名。预览「正在准备播放」阶段用的是同一个进度条组件（B 站直链本地化时能看到字节在走）。

**失败必须说清楚（2026-09）**：以前「选了 4 个只下来 2 个」是**静默**的 ——
下载失败（403 防盗链 / HTML 错误页 / 占位图 / 不是图片）直接丢掉，界面只报「已入库 2 个」，用户查无实证。
现在改成：

- **Referer 三档重试**：来源页 → 站点根 → 不带 Referer（图站规则各不相同：B 站认站点页、微博要根域、有些站带 Referer 反而 403）；
- **缩略图兜底**：原图仍取不到时退到搜索引擎缩略图，并在说明里写清「分辨率低一档」，不假装是原图；
- **逐条报账**：入库结束弹「有几条要跟你说清楚」，列出「名字：原因」——HTTP 403（站点防盗链）/ 不是图片（`text/html`）/ 只有 812 字节（疑似占位图）/ 连不上·超时 / 没解析出可下载直链…；
- **能重试**：失败或走兜底的候选保持勾选，再点一次「采集选中」即可重试；被「入库上限」拦住的部分也会明说「还有 N 个没下，上限是 M 个」；
- 视频条目若视频本体没下下来（只存了链接+封面），同样在说明里点名。

### 文章 / 小说采集（2026-09：直接转成 .md）

采集类型多了**文章**与**小说**：不进 `source` 素材库，而是**正文转成 Markdown，直接写成工作台里的 `.md` 笔记**
（文件名 = 标题，重名自动加序号；开头一行 `> 来源：<原始链接> · 采集于 时间`）。

**搜索后端**：`360 搜索 → 搜狗 → Bing` 依次尝试（谁先给结果用谁）。
原因是实测：Bing 网页端在国内网络下常只按**首个词**返回结果（同一台机器上图片/视频接口正常），
搜狗连续请求几次就会弹验证；360 的结果相关、跳转也能还原。
结果链接多为 `so.com/link?m=…` / `sogou.com/link?url=…` 跳转，入库前会并发解一层
（`window.location.replace("…")` 或 meta refresh）拿到真实地址；解不开就保留跳转链接（点开也能到）。

**正文提取**：容器启发式 —— `<article>` / `<main>` 优先，其次 id/class 像正文的块
（content / article / chaptercontent / 正文 / 阅读…），评分 = 文本量 − 链接密度×2.5，兜底整页。
标签转换覆盖标题、段落、列表（可嵌套）、引用、行内代码、围栏代码块（带语言）、链接（相对→绝对）、
图片、表格（补分隔行）、分割线；`&nbsp;` / `&#x4E2D;` 这类实体全部解码；
`script/style/nav/footer/aside/form` 整段丢弃；小说站常见的「请记住本站 / 最快更新 / 加入书签 / 上一章」
这类**短行**广告与导航会被清掉（长行不动，避免误伤正文）。
入库前还有两道体检：正文 < 200 字直接判「列表页 / 反爬页」，
**链接文字占比 > 50%** 判「这页正文基本是导航/评论（正文多半是动态加载的）」——
两种都不写文件，只在结果里说明原因（避免存下一篇全是导航链接的「笔记」）。

**小说**：目录页里按「第 X 章 / 第 12 节 / 第 12 回」找章节（阿拉伯与中文数字都认，
「第一零零回」也按 100 算），按章节号排序；只有页面里确实有带号链接时，才认目录容器里的无号链接
（否则百科/导航站会被当成小说）。抓取按「章节上限」截断，每章各自转 Markdown，
再拼成「`# 书名` + 每章 `## 标题`」；哪几章没抓到会在结果里点名。

**入库反馈**：和图片/视频一样走主题化进度条（小说按「第几章/共几章」走），
完成/失败都进「有几条要跟你说清楚」；候选卡上会回填「`12/30 章 · 8.6 万字 → 书名.md`」这类结果行，
底部还多一个「打开刚采集的笔记」按钮（直接跳到编辑器看结果）。

## 插件主题适配规范（所有插件界面必须遵守）

> 现在共有 4 套主题：**雾青 / 墨纸 / Bubble Pop（亮色）+ 深林夜（暗色）**。
> 插件界面不允许写死颜色与字体——它必须像应用自身的界面一样，跟着当前主题变。

**必须使用主题变量（禁止硬编码色值）**

| 用途 | 变量 |
| --- | --- |
| 页面底 / 面板 | `--bg` / `--surface` |
| 正文 / 次级文字 | `--text` / `--text-secondary` |
| 分隔线 / 描边 | `--border` / `--border-strong` |
| 强调（按钮、进度、选中） | `--accent` / `--accent-ink` / `--accent-soft` |
| 目录色 / 分类色 | `--h1` `--h2` `--h3` `--strong` `--em`（主题的多彩钩子） |
| 代码与行内代码 | `--code-bg` `--code-text` `--hl-*` |

**字体跟着主题走**

- 标题 / 展示文字：主题 `displayFont`
- 正文 / 界面文字：主题 `uiFont`（未声明时用系统字体）
- 代码 / 数字：主题 `codeFont`
- 插件不得自带字体；字号仍由用户滑杆控制

**表现细节**

- 圆角与间距用固定刻度（4 / 8 / 12 / 16），不跟随主题（保证一致性）
- 动效时长取主题 `motion.durationMs`，并尊重系统「减少动态效果」
- 半透明色必须由主题色现算（如 `--accent` 12% 叠底），不允许写死 `rgba(...)`
- 对比度跟随主题门槛：正文 ≥4.5:1、次级 ≥3.5:1（暗色主题同样适用）
- **进度 / 加载反馈**：轨道 = 主题正文色 12~14% 现算、填充 = `--accent`（渐变两端都取自 accent），
  百分比与字节数走主题 `codeFont`，说明文字走 `uiFont`；**拿不到总长时用「不确定」流动条，
  不许假装百分比**；次级文字也不能用系统 `.secondary`（自定义深底上看不清），必须由 `--text` 降透明度现算。
  参考实现：[ThemeProgressBar.swift](../Sources/MarkNote/Views/ThemeProgressBar.swift)，
  四主题对照图 [theme-progress-bar.png](screenshots/theme-progress-bar.png)
  （`THEME_SHOT_DIR=docs/screenshots swift test --filter ThemeProgressBarRenderTests` 可重新生成）。

**验收方式（硬要求）**

每个插件包提交时必须附一张**四主题对照图**（同一界面 × 雾青 / 墨纸 / Bubble Pop / 深林夜），
并标明每个颜色取自哪个变量。缺这张图，或出现任何硬编码色值，不进插件市场。

> **例外：流程图（`view-flowchart`，2026-09 修订）**
> 流程图是画图工具，**图形与连线的颜色允许用户自选**（调色板取自主题派生色，另可取色器任选），
> 因此画布内容不受「禁止硬编码色值」约束，四主题对照图也只针对**界面外壳**
> （工具栏 / 检查器 / 画布纸底 / 网格 / 默认配色与字体）。
> 外壳仍必须取主题变量；用户没改过的图形默认跟随主题，主题切换后默认色随之变化。
